# StreamLingo

> "I don't need instant translation. I need correct understanding."

StreamLingo is an accuracy-first conversation translator for interviews and other high-stakes conversations.
It intentionally uses controlled latency (default 5-10 seconds) so translation can use context instead of guessing too early.

## ✨ Features

* Local audio capture from selected input device (mic or virtual device like BlackHole)
* Streaming chunker with adaptive VAD gating
* `faster-whisper` STT stage (with optional mock fallback if dependency is missing)
* Context window buffer for translation continuity
* LLM translation adapter (OpenAI provider or mock passthrough)
* Ordered delay queue for stable controlled-latency subtitle emission
* Live subtitle UI over WebSocket
* Structured logging to JSONL and SRT export for review
* Replay endpoint to rerun translation on saved transcripts

### 🆕 Smart VAD (Voice Activity Detection)

StreamLingo now includes an advanced multi-stage VAD pipeline that improves speech segmentation and translation accuracy.

#### 🔹 Key Improvements

* Replaces fixed 2-second chunking with adaptive segmentation
* Emits audio at natural speech boundaries
* Filters silence and background noise
* Detects speaker changes in two-person conversations

#### 🔹 Enable Smart VAD

```bash
export SL_USE_SMART_VAD=true
```

Optional tuning:

```bash
export SL_SILERO_THRESHOLD=0.50
export SL_VAD_MIN_SILENCE_MS=400
export SL_VAD_MIN_SPEECH_MS=250
export SL_VAD_MAX_UTTERANCE_MS=15000
```

By default, Smart VAD is disabled to preserve existing behavior.

#### 🔹 Pipeline Overview

```text
AudioFrame
  │
  ▼ Gate 1 — Adaptive RMS (free, kills obvious silence)
  │
  ▼ Gate 2 — Silero VAD ONNX (~1–3ms/frame, confirms speech vs noise)
  │
  ▼ Gate 3 — VADSegmenter (slope + silence timer + speaker envelope)
  │
AudioChunk (complete utterance, natural boundary)
```

#### 🔹 Gate 3 Intuition (Slope-based turn detection)

* Treat the Silero speech probability as a **time-series signal**.
* While the **slope is rising or flat**, the speaker is mid-utterance → **keep buffering**.
* When the **slope drops and stays low**, the utterance is winding down.
* After a configurable **silence gap** (e.g., ≥ 400 ms), **emit the chunk**.
* A **sharp change in envelope shape** after silence indicates a **possible speaker change** (two-speaker setting).

**Heuristics**

* *slope up/flat* → continue buffering
* *slope down + gap* → emit
* *post-gap envelope shift* → mark `speaker_changed=true`

This allows emission at **natural speech boundaries** instead of fixed windows, improving STT quality and downstream translation.

## Architecture

```mermaid
flowchart LR
  audioIn[AudioInputDevice] --> chunker[Chunker_SmartVAD]
  chunker --> stt[Whisper_STT]
  stt --> context[ContextBuffer]
  context --> translate[LLM_Translate]
  translate --> delayQ[DelayQueue_Ordered]
  delayQ --> ws[WebSocket_Subtitles]
  ws --> ui[Browser_SubtitlesUI]
```

> Chunker now uses a multi-stage VAD pipeline (Adaptive RMS → Silero → Segmenter)

## Quick Start

### 1) Install dependencies (uv)

```bash
uv sync
```

### 2) (macOS) route meeting audio if needed

* Install a virtual audio device such as BlackHole.
* Route Zoom/Meet output to that device.
* Set `SL_INPUT_DEVICE_INDEX` to the matching input index from `/devices`.

### 3) Configure environment

Create a `.env` or export vars in shell:

```bash
export SL_SOURCE_LANGUAGE=ja
export SL_TARGET_LANGUAGE=en
export SL_TARGET_DELAY_SECONDS=7.0
export SL_CHUNK_SECONDS=2.0
export SL_CONTEXT_MAX_SENTENCES=6
export SL_TRANSLATION_PROVIDER=mock
# export SL_TRANSLATION_PROVIDER=openai
# export OPENAI_API_KEY=...
```

### 4) Run backend

```bash
uv run --env-file .env -- python -m uvicorn app.main:app --reload --app-dir backend
```

Then open [http://127.0.0.1:8000](http://127.0.0.1:8000)

## API Endpoints

* `GET /health`: status + provider mode
* `GET /devices`: list available audio input devices
* `POST /pipeline/start`: start capture/transcribe/translate stream
* `POST /pipeline/stop`: stop the stream
* `POST /pipeline/replay`: replay translation from saved transcript JSONL
* `WS /ws/subtitles`: live subtitle events

Replay body example:

```json
{
  "jsonl_path": "runs/<timestamp>/events.jsonl"
}
```

---

## Accuracy-First Workflow

1. Run live session and collect logs under `runs/<timestamp>/`.
2. Review:

* `events.jsonl` for stage-by-stage trace
* `subtitles.srt` for translation quality and timing

3. Tune:

* `SL_TARGET_DELAY_SECONDS`
* `SL_CONTEXT_MAX_SENTENCES`
* translation prompt/model

4. Use `/pipeline/replay` on saved transcripts to iterate without recapturing audio.

## Important Configuration

| Variable                   | Purpose                     | Default       |
| -------------------------- | --------------------------- | ------------- |
| `SL_SAMPLE_RATE_HZ`        | capture sample rate         | `16000`       |
| `SL_FRAME_MS`              | capture frame size          | `30`          |
| `SL_CHUNK_SECONDS`         | STT chunk duration          | `2.0`         |
| `SL_VAD_RMS_THRESHOLD`     | RMS sensitivity             | `0.010`       |
| `SL_TARGET_DELAY_SECONDS`  | controlled output latency   | `7.0`         |
| `SL_CONTEXT_MAX_SENTENCES` | translation context window  | `6`           |
| `SL_WHISPER_MODEL`         | whisper model size          | `base`        |
| `SL_WHISPER_DEVICE`        | whisper device target       | `auto`        |
| `SL_TRANSLATION_PROVIDER`  | `mock` or `openai`          | `mock`        |
| `SL_OPENAI_MODEL`          | OpenAI model name           | `gpt-4o-mini` |
| `SL_INPUT_DEVICE_INDEX`    | selected input device index | unset         |

## Current Limitations

* No diarization (single mixed speaker stream)
* Speaker change detection is optimized for two-speaker conversations
* Translation quality depends on selected provider/model
* TTS speech output is not part of MVP yet

---

## Roadmap

* Improve multi-speaker diarization support
* Add Redis-backed context/session state

## Why Subtitles First

Subtitles are the fastest way to validate correctness.
Once transcript + translation accuracy is stable, adding speech-to-speech (TTS output) is straightforward and lower risk.
